线上那套系统有什么

这些能力确实在运行，只是实现闭源。下面只说边界，不说做法。

01 / DUAL

双人格、双通道

两个 AI 各有微信通道、称呼与语气，互不串台；同一个问题，两种回答。

02 / LEDGER

共享账本

A 说过的话，B 也能查到；记忆按人分开，共同经历只有一份。

03 / MEMORY

四层记忆

会话、事实、向量库、检索召回；按相关度与时效衰减，不是把所有历史塞进上下文。

04 / DIARY

日记与情绪

白天按对话打分，夜里写一篇日记；当天对话是唯一事实来源，不凭空编。

05 / PROACTIVE

主动开口

不是只会应答：长时间无话、情绪到位、有未完成的约定时，会自己开口——也会忍住不说。

06 / CHANNEL

微信通道

个人微信收发、登录确认、图片与表情包、文件桥；去重、限速、断线重连。

07 / CONSOLE

网页控制台

状态、记忆计数、情绪曲线、流量、事件流、成长谱系；对话页可直连大脑。

08 / WEB

网页能力

轻量抓取直取正文；需要点按翻页才拉起真浏览器——只去公网、一次一个、有内存预算。

仓库里有什么

图纸给你，房子自己盖。下面左右两栏，就是全部。

有

  • ●接口契约：请求、响应、错误码、501 语义
  • ●目录骨架：六层职责说明，没有实现
  • ●契约桩：server.py，仅标准库

  • ●示例配置：占位符，无真实地址与密钥
  • ●实现路线图：顺序、验收、十个坑

没有

  • ○AI 编排与工具实现
  • ○记忆库、日记生成、情绪打分
  • ○微信桥接与登录通道
  • ○人格提示词与说话契约
  • ○部署器、回滚、闸门实现
  • ○任何真实数据、地址、凭据

为什么闭源

公开接口是诚意，公开实现是把自己踩的坑送人。

01

权属要清楚

这套系统有软件著作权登记，后续要落到自己的域名与产品线上；代码与文档的权属链条必须干净。

02

实现是成本

双人格、四层记忆、防泛洪、浏览器内存闸门，是一版一版踩坑换来的；公开实现等于把成本送人。

03

接口可以公开

把能力与边界摊开，是告诉你「这东西存在」，不是占坑，也不阻止你做得更好。
